## 0. 先说清楚四件事（避免做错方向）

1. **一级工作台只有参考图 1 一种样子。** 参考图 2/3/4 只用于二级业务页，绝不在一级工作台出现。

## 1. 三级交互结构定义

### 1.1 三层职责

| 层级 | 名称 | 职责 | 视觉承接 | 在这一层**不做**什么 |
|---|---|---|---|---|
| **L1** | 中央工作台（一级） | 只回答"我要去哪一类工作"。9 个入口 + 中央状态文案 | 参考图 1：紫黑褶皱 Canvas + 磨砂圆盘 + 9 环绕图标 | 不显示项目数据、不做表单、不显示侧栏 |
| **L2** | 功能空间（二级） | 完成一类完整任务，承载该类目下所有真实路由，可在子功能间切换 | 按页面性质选用图 2 / 图 3 / 图 4 / 动态透视卡片（见 §5） | 不再套一层暗色圆盘，不做第二个侧栏 |
| **L3** | 操作面板（三级） | 单个局部动作：新建、确认、筛选、详情预览、设置弹层 | 从当前 L2 语言生长的浮层/抽屉，保留 1px 亮边与紫光晕 | 不改变 URL、不新建页面层级；Esc 即关闭 |

**承接关系（一句话）**：L1 用"盘心放大淡入"把用户送进 L2（380–420ms）；L2 顶部始终有「工作台 › 入口 › 当前页」面包屑与「全部功能」按钮；L3 只在该页内部浮出，关掉就回到原页。

- 每个入口的**全部**子功能都放进该入口的「全部功能」浮层；主路由只是默认落地点，不是唯一入口。

> 所有时长与缓动均引用视觉规范 §5；下面只规定"什么时候用哪条数值"以及中央文案/其他图标的变化。

| 状态 | 触发条件 | 视觉反馈（引用 §5 数值） | 中央区文案 | 其他 8 个图标权重 | 可恢复 |
|---|---|---|---|---|---|
| **S0 默认态** | 进入工作台 / 取消操作 / 返回工作台 | 图标静止；背景按 §2.4 以 20–28s `linear` 缓慢流动 | `Release to Select`（11–12px / 500 / `#5B4A6B`） | 全部等权，opacity 1 | — |

| **S3 拖动选中态** | 指针从内圈按下并移动超过阈值，指向某方向 | 同 S1，目标图标额外加 1px `#C084FC` 外环；无 hover 事件依赖 | 两行文案 + 第三行 `松手进入`（Caption 12px） | 降至 **opacity .45**，强调方向感 | 回到死区 → S0；移出取消区 → S0 |

**状态切换硬规则**

- S1 → S2 与 S3 → S2 的结局必须完全一致（同一跳转函数），拖动不能成为唯一通路。
- 任何状态下按 `Esc`：S3 → S0；L3 浮层 → 关闭；L2 无浮层 → 返回 L1（若有未保存数据先走 §8.3）。
- 转场期间（S4/S5）禁止重复触发导航：给圆盘容器加 `pointer-events:none`，时长与转场一致。
- `prefers-reduced-motion: reduce` 时：跳过 `scale`、涟漪、背景流动，只保留 120ms 淡入淡出；状态差异改用**边框颜色 + 文字变化**表达（见 §7.3）。

## 4. 拖动径向选择（可选加速手势，不强制学习）

### 4.1 一句话规则

**在内圈按住 → 朝某个图标方向拖动 → 该方向图标高亮 → 松手进入该入口**。全程可取消，且**传统点击始终可用**。

### 4.2 详细规则（按时间顺序）

1. **起点**：`pointerdown` 必须发生在内圈 `.rc-core` 内（不是图标上）。触屏给内圈设 `touch-action: none`，防止页面手势抢走事件。
2. **激活阈值**：指针离开按下点 **> 8px（鼠标）/ > 12px（触摸）** 才进入拖动态。阈值内松手 = 什么也不做，只显示一次提示「点击图标，或按住中心向方向拖动」（3s 后淡出）。这一步防止误触。
3. **指针捕获**：激活后对内圈调用 `setPointerCapture`，即使手指/鼠标移出圆盘也持续跟踪。
4. **角度计算**：以圆心为原点，计算指针向量与 12 点方向的夹角 `θ`（顺时针为正，0–360°）。9 个图标各有固定角度 `θᵢ`（见 4.4）。
5. **命中判定**：采用**最近角度**原则 —— 选中 `argmin(环形距离(θ, θᵢ))` 的图标。这比"固定 ±20° 扇区"更稳，因为原图 9 个图标的间隔本来就不均匀。
6. **死区**：指针到圆心距离 `r < 0.08W`（≈`0.52R`，刚好越过奶白内圈边缘 `0.40R`）时**不选中任何图标**，中央文案保持 `Release to Select`，避免刚开始拖动就跳变。
7. **理想命中带**：`0.08W ≤ r ≤ 0.12W`（≈`0.52R–0.77R`，以图标环 `0.10W ≈ 0.66R` 为中心、上下各 `0.02W`）进入 S3，目标图标按 S1 规则高亮 + 外环，中央文案换成入口文案 +「松手进入」。
8. **宽容区与取消区**：`0.12W < r < 2R` 时继续按最近角度高亮（手指/鼠标过冲不丢失选中，这是方向手势的必要宽容度）；`r > 2R`（或指针移出浏览器窗口）视为取消，立刻回 S0，松手不导航。这是给用户的"反悔出口"。
9. **松手**：`pointerup` 时若有有效目标 → 执行与点击完全相同的跳转（S2 → S4）；若无目标 / 已取消 → 320ms 回弹到 S0。
10. **键盘等价**：`← / →` 沿图标环逆时针 / 顺时针移动焦点，`Home / End` 跳到 12 点 / 最后一个图标，`Enter / Space` 选中。拖动是"锦上添花"，不是必经路径。

### 4.3 伪代码（交互算法，可直接翻译为 TS）

```text
onPointerDown(e):
  if 目标不是内圈: return              // 点在图标上走普通点击
  start = {x:e.x, y:e.y}; captured = false

onPointerMove(e):
  d = distance(e, start)
  if !captured and d < 阈值: return
  if !captured: captured = true; setPointerCapture()

  v = e - center; r = |v|
  if r > 2*R: 取消高亮; state = S0; return        // 取消区
  if r < 0.08*W: 取消高亮; state = S0; return     // 死区（内圈内）

  θ = atan2(v.x, -v.y) 归一到 [0,360)
  i = argmin_i 环形距离(θ, θᵢ)                    // 0.08W–0.12W 为理想命中带；
  高亮图标 i; state = S3; 中央文案 = 入口 i 的文案 + "松手进入"  // 0.12W–2R 为宽容区

onPointerUp(e):
  if captured and state == S3: 进入(i)
  else if captured: 回 S0（不导航）
  else: 显示一次性提示（点击或拖动）
  releasePointerCapture()
```

### 4.5 图标环半径（已校准，写死此值）

旧的 0.44R 与 145–155px 互相矛盾，原因是视觉规范早期混用了「预览图坐标」与「源文件坐标」两套单位。视觉负责人已用 PIL 按源文件实测校准（源文件 1440×922，外盘中心 ≈(705,490)，外盘半径 ≈220px，内圈半径 ≈95px，9 图标中心距圆心 108–169px / 均值 ≈145px），并更新了视觉规范 §1.1 / §1.3 / §1.4 / §8，旧值作废。

**最终使用值（本规范与前端实现均按此写死）：**

| 量 | 相对值 | 换算（设计画布 D=0.31W 时） |
|---|---|---|
| 外盘半径 `R` | `0.5D` | `0.155W` |
| 内圈半径 | `0.20D`（内圈直径 `0.40D`） | `0.062W` |
| **图标环半径** | **`0.66R`（≈`0.33D`）** | **`≈0.10W`** |
| 理想命中带 | `0.52R–0.77R` | `0.08W–0.12W` |
| 拖动死区 | `<0.52R` | `<0.08W` |
| 拖动取消区 | `>2R` | `>0.31W` |

- 图标**贴在磨砂盘内侧环带**（介于奶白内圈与外盘边缘之间），所以点击热区不得延伸到盘外背景上。
- 静态点击热区以图标中心为圆心、直径 ≥44px（手机 ≥48px）；窄屏时热区可覆盖命中带上下边界，但不得越出外盘边缘。
- 拖动的宽容区（`0.12W–2R`）是刻意保留的：方向手势靠角度而非像素级命中，过冲不丢选中才顺手；理想带只是反馈最强的区域，不是硬边界。

### 4.6 "点击永远可用"的四条保证

1. 图标本身始终是独立可点元素，`onClick` 不依赖拖动状态。
2. 首次进入工作台显示一次底部提示（3s），明确告知两种操作都行；之后不再打扰。
3. 帮助/首次提示里**先讲点击、后讲拖动**，拖动被描述为"更快的方式"而非"正确方式"。
4. 键盘用户完全不需要拖动（方向键 + Enter 即可），触屏用户可直接点击（见 §6.3）。

## 6. 移动端与多端适配

### 6.1 断点与圆盘尺寸

| 断点 | 宽度 | 外盘直径 `D` | 内圈直径 | 图标环半径 | 图标视觉尺寸 | 最小点击热区 |
|---|---|---|---|---|---|---|
| 桌面 | ≥1024px | `clamp(300px, 31vw, 460px)` | `0.40D` | `0.66R ≈ 0.33D ≈ 0.10W` | 线框 22–26px；App 方块 34–38px | ≥44×44 CSS px |
| 平板 | 640–1023px | `clamp(280px, 38vw, 380px)` | `0.40D` | `0.66R ≈ 0.33D` | 线框 20–24px；方块 32–36px | ≥48×48 |
| 手机 | <640px | `min(86vw, 340px)` | `0.40D` | `0.66R ≈ 0.33D` | 线框 20–22px；方块 30–34px | ≥48×48 |

- 图标的**视觉尺寸**可以小，但**透明热区**必须达到上表数值（用伪元素扩展，不改变外观）；热区以图标中心为圆心，**不得越出外盘边缘**（图标在盘内侧环带里）。

- 极端降级：仅当 `D < 240px`（极窄屏，间距降到 ≈55px）时，把 9 个图标改为 2 行卡片列表（仍从内圈「展开全部」触发，不是侧边栏），保证不重叠。

## 8. 返回工作台与上下文保持

### 8.1 现有能力（真实存在的字段，不要夸大）

`uiStore` 已有三个字段，且已有代码在写入：

| 字段 | 当前写入位置 | 用途 |
|---|---|---|
| `lastProjectId` | `useTrackProject(projectId)`，被各项目页调用；`ProjectTeamPage` 也直接写入 | 生成带项目 id 的链接 |
| `lastPlanId` | `ReproductionPlanPage` 的 useEffect | 直达最近规划 DAG |
| `lastRunId` | `ReproductionConsolePage` 的 useEffect | 直达最近执行控制台 |

**重要事实**：当前 `uiStore` 是内存态 Zustand，**没有 localStorage 持久化**，浏览器刷新后这三个值会清空。本文不声称"刷新后仍能恢复"；若要跨刷新保持，属于额外需求，需单独实现，不在本次范围。

### 8.2 返回工作台的三种方式（统一收敛到同一函数）

1. L2 面包屑的「工作台」；
2. L2 页眉的返回按钮（手机端固定左上）；
3. 浏览器后退（React Router 的 `navigate(-1)` 兼容）。

三者都调用同一个 `returnToWorkbench()`：先处理未保存数据（8.3）→ 写入上下文 → 320ms 转场回 L1。

### 8.3 不丢未保存数据的策略（按优先级）

> 现状代码没有通用的草稿持久化；以下是**给 Phase 3 的实现规范**，不要对外说"已经支持自动保存"。

1. **第一优先：表单类页面自动存草稿。** 输入变化后 300ms 防抖写入 `sessionStorage`，键名 `rc:draft:<路由模板>:<id>`；页面重新进入时先读草稿恢复，用户确认提交/取消后才清除。适用于：新建项目、规则编辑、字段配置、模型服务设置等 L3 表单。
2. **第二优先：不可自动保存的动作要确认。** 例如正在执行的复现运行、已上传但未提交的材料，离开前弹确认：「有正在进行的操作，确定离开吗？」「留在这里 / 仍然离开」。确认框是 L3 面板，Esc = 留在这里（安全默认）。
3. **标签页关闭/刷新**：用 `beforeunload` 只在存在草稿时提示。
4. **不要用 `useBlocker`**：项目用的是声明式 `<Routes>`（`react-router-dom 6.28.0`，非 data router），`useBlocker` 会报错。在应用内导航用上面第 1、2 条的显式机制即可。
5. 草稿只存用户输入，不存密钥、令牌等敏感值（`/api-tokens`、`/settings/llm` 的密钥字段永不写入 sessionStorage）。

### 8.4 回到工作台后的上下文呈现

- 回到 L1 后**不自动跳转**，保持图 1 原样；只在内圈文案下方多一行 Caption（12px，`#E9D5FF`）：
  `上次：项目 X · 规划 Y · 运行 Z`（只显示实际存在的值，最多一行，超长省略）。
- 再次点击需要 id 的入口时，直接使用这三个值补全路由（与 `AppLayout.tsx` 现有逻辑一致），用户不必重新选项目。

## 9. 高风险交互与降级方案（汇总）

| 风险 | 触发场景 | 后果 | 降级 / 防护 |
|---|---|---|---|
| 拖动误导航 | 用户想滚页面却从中心划出 | 跳进错误入口 | L1 页面本身不滚动；8/12px 激活阈值；`r<0.08W` 死区；`0.08–0.12W` 理想命中带；`r>2R` 取消区；松手前文案明确「松手进入」；点击始终可用 |
| 无项目上下文点带 id 的入口 | 首次使用、刷新后 | 空白详情 / 报错页 | 用 `lastProjectId`，无则落 `/projects` + 页内提示（§2.5） |
| 未保存数据丢失 | 表单填一半就返回 | 用户返工 | 300ms 防抖草稿 + 离开确认；密钥类字段不落盘（§8.3） |
| 触屏无 hover，看不到入口说明 | 手机上 9 个图标只有符号 | 不知道点哪 | 点击直达；介绍文案在 L2 页顶部补一次；首次底部提示；长期可长按预览 |
| 图标太密导致误点 | 窄屏 / 大字体设置 | 点错入口 | 热区 ≥48px 且互不重叠；间距按 §6.1 核算；极窄屏降级为 2 行卡片列表 |
| 动效引起不适 | 前庭敏感用户 | 眩晕 | 完整 `prefers-reduced-motion` 降级（§7.3），反馈不丢失 |
| 二级语言串味 | 把图 3 扇形塞进数据审计页 | 视觉混乱、返工 | 按 §5 固定映射，一个 L2 空间内不换语言；一级永远图 1 |

| 虚假功能入口 | 用户要求"代码中心" | 点了没内容 | 不建该入口；用复现规划 DAG / 环境替代并说明（§2.4） |
