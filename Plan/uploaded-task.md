ReproCheck 全层级 UI 视觉统一与交互重构任务

一、任务名称

ReproCheck 一级工作台、二级功能空间、三级业务页面视觉统一重构

本次任务以我提供的三张实际运行截图作为设计依据：

- 第一张：一级页面，主工作台。
- 第二张：二级页面，功能空间。
- 第三张：三级页面，项目档案。

请严格按照这三个层级理解现有产品结构，不要混淆页面职责。

本次不是单纯修改颜色、圆角或字体，而是要从图标系统、布局结构、视觉层次、导航体系、卡片排列、中文本地化和交互体验等方面完成一次真正的 UI 优化。

第一张图片是整个系统的最高视觉基准，第二张是本次重点改造对象，第三张是需要同步统一的实际业务页面。

必须直接修改现有项目代码，并在浏览器中运行验证。

---

二、总体设计原则

1. 第一张图片确定全站视觉语言

第一张主工作台已经形成了具有辨识度的设计风格：

- 紫色、淡紫色与深色背景的组合。
- 中心圆形工作台。
- 环绕式功能入口。
- 柔和的光影与半透明视觉效果。
- 具有空间层次感的背景。
- 简洁、克制、具有科技感的界面。

这些设计特点需要保留，并作为全站统一的设计语言。

但必须明确：

统一视觉语言，不代表所有页面使用相同布局。

一级页面继续采用环绕式工作台。

二级页面采用清晰的功能入口布局。

三级页面采用符合实际业务需求的管理界面。

不同页面可以有不同的结构，但必须让用户一眼看出它们属于同一个产品。

2. 建立统一设计规范

先检查现有项目的 CSS、组件、主题变量和 UI 库。

建立一套统一的 Design Tokens，至少包括：

- 主背景色。
- 次级背景色。
- 紫色强调色。
- 淡紫色辅助色。
- 卡片背景色。
- 卡片边框颜色。
- 标题文字颜色。
- 正文文字颜色。
- 次要信息颜色。
- 图标颜色。
- 按钮颜色。
- 阴影与光效。
- 圆角规范。
- 页面间距。
- 卡片间距。
- 字体与字号层级。
- 动画时长与缓动曲线。

建议围绕深紫色、低饱和薰衣草紫、淡紫白和深色背景建立色彩体系。

不要再出现一级页面明显偏紫、二级页面随意使用其他颜色、三级页面大面积使用蓝色的情况。

不要求所有组件都使用紫色填充。

应通过背景、边框、光影、强调色和材质建立联系，避免整个页面变成一片紫色。

禁止为了统一配色而简单地给所有卡片套上紫色玻璃背景。

三、一级页面：主工作台图标系统全面统一

本次必须重点检查第一张图片中的所有功能图标。

1. 全部图标重新规范

当前图标存在明显的视觉不一致问题：

- 部分是线性图标。
- 部分是实心图标。
- 部分带有蓝色方形背景。
- 部分图标尺寸明显不一致。
- 部分图标的视觉中心发生偏移。
- 个别图标看起来像来自不同的图标库。

必须进行统一处理。

要求：

1. 全部普通功能图标采用统一的图标设计体系。
2. 优先使用统一的 SVG 图标组件，不要混用来源不明的图片和图标。
3. 统一 SVG 画布尺寸、描边粗细、线条端点、圆角和视觉比例。
4. 统一图标主体颜色，优先使用深紫色或与当前工作台匹配的颜色。
5. 统一图标容器的尺寸和视觉边界。
6. 不允许某些图标单独出现突兀的蓝色背景或黑色底板。
7. 不允许普通功能图标使用不同的立体风格、线性风格和实心风格混搭。
8. 不允许出现图标内容被拉伸、压扁或裁切的情况。

2. 重新校准环绕式图标的位置

以中心圆盘为定位基准，检查每一个外围图标。

要求：

- 所有图标必须处于合理的环绕位置。
- 同一环绕区域内的图标视觉尺寸一致。
- 每个图标都必须位于自身容器的几何中心。
- 图标之间保持均衡的角度和间距。
- 不允许图标与中心圆盘发生重叠。
- 不允许图标过于靠近圆盘边缘。
- 不允许部分图标明显偏高、偏低或偏离环绕轨道。
- 不允许图标容器旋转后导致图标本身倾斜。

请使用规范化的布局计算方式管理环绕位置，不要通过大量零散的绝对定位数值逐个手动凑位置。

3. 图标交互规范

所有外围功能入口必须具有一致的：

- 默认状态。
- 鼠标悬停状态。
- 点击状态。
- 焦点状态。
- 禁用状态（仅适用于真实存在禁用逻辑的功能）。

悬停时可以有轻微放大、柔和光晕或位移，但不能出现明显跳动。

图标不允许因为悬停动画而改变原本的排列位置。

所有图标必须对应真实功能，不能为了视觉统一而改变原本的业务含义。

四、二级页面：重点重构功能空间

第二张图片是本次改造的重点。

目前最严重的问题是三个功能卡片明显重叠，背景装饰和内容相互干扰。

必须从布局层面解决，而不是简单调小卡片。

1. 彻底解决卡片重叠

当前页面有三个功能入口：

- 项目列表
- 新建项目
- Bloom 项目工作台

必须保留原有功能和跳转关系。

重新设计这三个入口。

硬性要求：

1. 三张卡片必须完全独立。
2. 卡片之间必须有明确的垂直或水平间距。
3. 卡片的边界不能发生任何重叠。
4. 文字、编号、箭头不能被其他元素遮挡。
5. 卡片不能互相覆盖。
6. 卡片不能因为悬停动画而与其他卡片碰撞。
7. 不能出现文字压线、箭头越界、边框交错的问题。
8. 页面缩放或窗口尺寸变化时，卡片布局必须自动适配。

优先采用居中的纵向功能卡片列表，或者经过合理规划的网格布局。

不要继续使用目前这种三张卡片彼此压叠的展示形式。

卡片间距必须足够，使用户能够清晰地区分每一个功能入口。

2. 重新整理页面视觉层次

保留第一张图片中的紫色花瓣放射式背景语言，但二级页面不能让所有装饰元素都与内容争抢注意力。

要求：

- 页面标题清晰。
- 页面说明文字紧随标题。
- 功能入口形成清晰的视觉分组。
- 卡片背景与背景壁纸具有足够的明度和透明度差异。
- 背景装饰不能穿过重要文字。
- 虚线圆环不能覆盖卡片内容。
- 背景中的图标不能与功能卡片中的图标产生混淆。
- 主要功能入口必须拥有最高的视觉优先级。

可以适度降低装饰圆环的透明度，或者调整其位置和尺寸。

如果装饰圆环影响主要内容，应当缩小或移除，而不是为了保留装饰而牺牲可用性。

3. 卡片设计要求

三个卡片应当具有统一的设计规范：

- 相同的圆角体系。
- 相同的卡片高度体系。
- 相同的内部间距。
- 相同的编号位置。
- 相同的标题对齐方式。
- 相同的副标题位置。
- 相同的箭头位置。
- 相同的边框与阴影风格。

可以使用柔和的半透明材质，但必须保证文字清晰。

悬停时允许轻微上浮、边框增强和柔和光效。

禁止：

- 卡片互相重叠。
- 卡片无限叠层。
- 不合理的倾斜角度。
- 过度的旋转动画。
- 过度的透明效果。
- 无意义的大面积发光。
- 影响阅读的装饰元素。
- 为了追求视觉效果而牺牲点击区域。

4. 页面导航与提示文字

将 "FUNCTION SPACE" 改为“功能空间”。

将 "SELECT A REAL ENTRY" 改为“选择功能入口”。

如果存在其他类似英文装饰文字，也需要检查并本地化。

页面中应当明确告诉用户当前所在的位置，以及点击不同卡片后会进入什么功能。

五、三级页面：项目档案界面优化

第三张截图是实际业务页面。

不能将它简单地改成第一张图片的环绕布局。

它应该保留管理页面应有的信息组织能力，同时继承一级工作台的设计语言。

1. 顶部导航栏重新设计

目前三级页面上方的导航区域过于拥挤，尤其是“目录”“工作台”和页面面包屑之间的距离不合理。

请重新组织顶部布局。

建议按照以下结构处理：

左侧：

- 目录入口。
- 返回工作台入口。
- 当前页面面包屑。
- 当前页面标题。

右侧：

- 全屏操作。
- 日期信息。
- 用户信息。
- 其他实际存在的系统操作。

要求：

1. 不要让“工作台”按钮与页面标题挤在一起。
2. 不要让目录按钮、返回按钮和面包屑互相挤压。
3. 减少不必要的按钮外边距。
4. 统一按钮高度和圆角。
5. 统一图标与文字的垂直对齐。
6. 右侧操作区应当分组排列。
7. 日期等次要信息不要占据过多空间。
8. 在较窄屏幕中，应当自动调整导航布局，而不是让组件互相覆盖。
9. 顶部导航必须有清楚的主次关系。

特别要求：

“返回工作台”应该是一个简洁、明确的导航入口，不要做成一个过大、过厚、占空间的按钮。

可以采用小型返回入口加面包屑的形式，留出足够的标题空间。

2. 统计卡片统一配色

当前第三张图片中的统计卡片偏向浅蓝色，与前两级页面不够统一。

需要调整为统一的紫色视觉体系。

具体要求：

- 卡片可以使用深紫色半透明背景。
- 可以使用低饱和度的淡紫色边框。
- 重点数值使用高对比度文字。
- 辅助说明使用适当降低亮度的文字。
- 卡片之间使用统一间距。
- 统计数字需要有清晰的视觉层级。
- 不要出现过度模糊的玻璃质感。
- 不要为了营造高级感而降低文字对比度。

统计卡片应该清晰、简洁、可信。

3. 空状态设计优化

当前项目数量为 0 时，页面中央的大面积空状态区域显得比较空。

请在不虚构业务数据的前提下重新设计空状态。

要求：

- 清楚说明当前没有项目。
- 使用统一风格的图标。
- 提供明确的“创建项目”操作。
- 保持合理的留白。
- 不要让空状态区域占据过大的视觉面积。
- 不要出现不必要的大面积空白玻璃板。
- 创建按钮必须实际可用。

如果项目数量为 0，统计数字继续保持真实的 0，不得使用假数据填充页面。

六、全站中文本地化

本次必须对一级、二级、三级页面进行一次全面的界面文字检查。

原则：面向普通用户的文字，能使用中文的尽量使用中文。

以下英文需要优先处理：

原英文| 建议中文
FUNCTION SPACE| 功能空间
SELECT A REAL ENTRY| 选择功能入口
PROJECT ARCHIVE| 项目档案
PROJECT TOTAL| 项目总数
DOMAIN| 研究领域
PAPER| 关联论文
LATEST| 最近更新
AI| 人工智能 / 智能辅助
WORKBENCH| 工作台
PROJECTS| 项目列表
NEW PROJECT| 新建项目
AUDIT WORKBENCH| 审计工作台

注意：

1. "ReproCheck" 是产品名称，保留。
2. "Bloom" 如果是实际功能或模块品牌，可以保留，但后面应当有清晰的中文说明。
3. 编程语言、协议名称、技术标准、真实 API、代码路径等专业术语，可以保留必要的英文。
4. "/projects" 这样的路由地址可以保留在代码或开发者信息中，但不要把它作为普通用户主要阅读的内容。
5. "GET /projects" 等接口调试信息应当从普通用户界面中移除，或者放到开发者调试区域。
6. 不要为了中文化而翻译程序变量、接口字段、数据库表名和代码标识符。
7. 全站检查按钮、提示语、空状态、错误提示、表单字段、悬停提示、弹窗标题和导航菜单，不要只翻译首页。
8. 中文文案必须自然、准确、简洁，不能出现机械翻译。

最终应当形成一个以中文为主体、专业术语使用准确的科研软件界面。

八、实际执行步骤

请不要只输出设计建议。

按照以下顺序直接开展工作：

第一步：项目检查

- 检查当前项目目录。
- 阅读项目说明。
- 检查 Git 状态。
- 检查前端技术栈。
- 找到一级工作台页面。
- 找到二级功能空间页面。
- 找到三级项目档案页面。
- 找到对应的路由、组件和样式文件。
- 记录当前三个页面的真实结构。

第二步：建立视觉规范

先统一 Design Tokens 和图标组件。

检查现有图标资源，找出风格不同、尺寸不一致、位置偏移的图标。

不要在没有检查代码之前直接大范围覆盖样式。

第三步：重构一级页面图标

完成图标统一和位置校准。

确保原有功能入口没有丢失。

第四步：重点重构二级页面

彻底解决三个功能卡片重叠问题。

重新组织装饰元素和实际功能内容的层级。

确保三个功能入口清晰、独立、易点击。

第五步：重构三级页面

重新安排顶部导航。

统一统计卡片配色。

完善空状态。

完成页面中文化。

第六步：全站检查

检查三个页面以及它们之间的跳转关系。

确保没有新旧样式混用。

确保没有页面因为公共样式修改而产生其他布局问题。

九、严格测试要求

完成修改后，必须启动项目并使用真实浏览器测试。

至少完成以下检查：

7. 打开三级项目档案，检查顶部导航。
8. 检查“返回工作台”入口是否清晰。

10. 检查项目为空时的空状态。
11. 检查界面文字是否完成中文化。
12. 检查不同浏览器窗口尺寸下的布局。
13. 检查控制台错误和网络请求异常。
14. 检查是否存在被遮挡、被裁切或无法点击的组件。

至少使用桌面常见尺寸和较窄窗口尺寸进行测试。

建议使用 Playwright 进行路由遍历、截图和交互测试。

测试截图必须来自本次修改后的真实运行页面，不能拿以前的截图冒充。

发现问题必须修复后重新测试。
