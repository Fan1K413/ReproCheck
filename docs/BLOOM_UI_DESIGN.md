# Bloom UI —— 三级科研复现工作台设计规范

> 设计基线：2026-11-21。对应实现：`frontend/src/bloom/`。项目工作台路由 `/projects/:projectId/workbench`。
> 本文档只描述当前已落地版本，不再保留早期方案对比。

---

## 1. 设计命题

ReproCheck 的核心不是“管理表格”，而是把论文、材料、事实、证据、规划、环境、运行、结果、报告、协作这些彼此独立的证词放进同一个可核对的空间。

旧版工作台的问题是：所有功能都收束为一种白色花瓣，单击后都展开成同一张 1080×640 档案页，组合只剩两栏并排。形态没有承担业务差异，三级工作区也没有真正发生。

本版把体验拆成三个明确层级：

| 层级 | 空间 | 任务 | 交互结果 |
|---|---|---|---|
| 一级 | 绽放台 | 项目全景与功能入口 | 10 个科研单元以三种材质、三种轮廓围绕项目核分布 |
| 二级 | 形变面板 | 单个单元被展开为完整工作区 | 三种不同轮廓、尺寸、页眉密度与入场时长 |
| 三级 | 复现工坊 | 多单元在同一空间联动 | 模块库 + 中心图 + 真实节点 + 详情抽屉 + 就绪读数 |

三个层级不是三个割裂页面。一级的卡片可以直接进入二级，也可以沿 `btn-atelier` 进入三级；三级中的节点仍调用同一套 `UnitDetail`，不复制业务组件。

## 2. 形态系统：三类标本，而不是三套皮肤

`BloomMorph` 只有三个值：

```ts
type BloomMorph = 'folio' | 'lattice' | 'instrument'
```

映射固定在 `morphs.ts`：

| Morph | 单元 | 业务隐喻 | 收拢轮廓 | 展开尺寸 |
|---|---|---|---|---|
| `folio` | 论文与材料、科研事实、审计报告 | 可摊开的纸页、档案 | 厚纸标本板，左上装订角 | 1120 × 650 |
| `lattice` | 证据图谱、复现规划、协作与任务 | 关系格架、晶格 | 切角格架，六边形切边 | 1060 × 660 |
| `instrument` | 数据集与代码、实验环境、复现运行、结果验证 | 仪器面板、控制台 | 切角仪表盘，右下斜切 | 1180 × 610 |

这些差异必须同时出现在四个维度，不能只换颜色：

1. **轮廓**：`geometry.ts` 的 `closedPolygonFor` 用高指数超椭圆生成厚标本板，`panelPolygonFor` 用标准超椭圆参数化生成展开轮廓，并保留每个 morph 的 `notch / slash`。
2. **材质**：`bloom.css` 为纸面、格架、仪器分别提供底色、纹理、边缘线和层叠 underlay。
3. **页眉密度**：folio 使用宋体标题与装订线；lattice 使用网格底与更紧的指标条；instrument 使用顶部仪表条与等宽读数字体。
4. **运动**：`MORPH_META` 中 folio 760ms、lattice 700ms、instrument 620ms；初始旋转分别为 -4°、-10°、7°。

收拢态不使用尖椭圆。早期尖瓣会切掉标题、指标和底栏，本版改为“厚标本板”：仍是花瓣尺度，但四边留出安全边距，标题和指标始终完整可读。

## 3. 一级：绽放台

实现：`BloomStage.tsx`、`BloomCard.tsx`、`useBloomLayout.ts`。

### 3.1 空间结构

- 10 个单元分布在三条椭圆轨道上，轨道半径由舞台尺寸计算；卡片位置、倾角、缩放由 `bloomPlacements()` 生成。
- 中心核显示项目名、论文标题、真实覆盖分（如 `0.545`）、以及“打开复现工坊”入口。
- 中心核外圈有 10 个状态刻度，颜色对应单元 tone；状态来自真实接口，不是装饰。
- 轨道之间有极淡的放射虚线，从项目核指向每个单元，作为“花脉”而非粒子特效。
- 顶栏保留项目身份、单元分类脊线、成员、标准视图入口和工坊入口；底栏保留返回、旋转、组合、关联、工坊入口和刷新。

### 3.2 收拢态

- 卡片显示编号、morph 标签、单元英文 kicker、中文标题、一条主指标、状态点。
- `folio` 的标题使用宋体；`instrument` 的指标使用等宽字体；`lattice` 使用更密的行距和格架纹理。
- 卡片不是纯平面：每张卡有三层 DOM（`back underlay` / `mid underlay` / `surface`），层间有轻微偏移，形成标本板的厚度。
- 卡片边缘有一枚微型读数尺和状态点，只用真实指标，不生成装饰数字。

### 3.3 二级展开

- 单击卡片进入 `?focus=<unitId>`，卡片从轨道位置移动到舞台中央，轮廓过渡为对应的展开面板。
- 非活动卡片 dim 到 `0.16`，只保留空间记忆，不与主面板争夺视线。
- 展开面板的顶部工具固定为：装配进复现工坊、与其他单元组合、标准视图、收拢。
- 展开面板的正文使用统一 `UnitDetail`，底部提供主操作与真实数据来源说明。
- 当正文超过可视高度时，滚动区右下出现一个 `↓` 圆形提示；滚到底部自动消失。滚动条为细样式，不依赖隐藏手势。
- `Esc`、点击舞台空白、顶栏“收拢”都可关闭。

### 3.4 移动端

- 舞台宽度小于 900px 时，极坐标布局被拉直为纵向 chamfer 卡片列表，保留编号、kicker、标题、指标和状态。
- 展开面板变为固定全屏工作区，顶部保留返回/组合/外链/关闭，底部操作换行排列。
- 移动端不提供拖拽旋转；所有关键动作仍可通过顶栏、卡片和底栏完成。

## 4. 三级：复现工坊

实现：`BloomAtelier.tsx`、`useAtelierData.ts`、`atelier.css`。入口为 `?view=atelier`，路由复用工作台，不新增业务路由。

### 4.1 默认装配

默认 5 个模块：`materials,dataset,environment,runs,verification`。这五个正好构成最小复现闭环：材料 → 数据/代码 → 环境 → 运行 → 验证。

- 支持 2–6 个模块并置；少于 2 个时禁用移除。
- 模块库列出 10 个单元，活动模块显示 `−`，非活动显示 `+`；点击活动项选中，点击非活动项加入。
- 装配列表写入 URL `?modules=`，刷新、分享、回到页面都能恢复同一工作区。
- `?focus=` 同时控制图中选中节点与右侧详情，便于深链到某个模块。

### 4.2 空间结构

- 中央是 `PROJECT HUB`，显示项目名、论文标题、覆盖分、模块数、就绪数。
- 中心周围按真实模块位置分布节点卡；节点之间根据 `pair relation` 画曲线，标签使用真实关系名（如“提供数据契约”“产生指标”“监控运行”）。
- 节点卡不是统一白色矩形：`bloom-atelier-node--folio/lattice/instrument` 分别使用纸面、格架、仪器材质，并保留不同切角。
- 节点上显示真实指标、状态、角色和一条 note；note 超出一行时省略，不伪造摘要。
- 右侧详情复用 `UnitDetail`，不复制页面；桌面宽屏常驻，窄屏变为覆盖抽屉，移动端为全屏抽屉。
- 底部 readiness 条显示整体分、平台评分说明、环境缺失/失败运行/事实证据等真实读数，以及刷新按钮。
- 左侧模块库底部固定边界说明：并置模块不合并业务对象，不改变权限，移除模块不会删除后端数据。

### 4.3 响应式

| 宽度 | 工坊形态 | 详情形态 |
|---|---|---|
| > 1180px | 左库 + 中央图 + 右详情三栏 | 右侧常驻栏 |
| 901–1180px | 左库 + 中央图，详情覆盖在图上 | 绝对定位右侧抽屉，带关闭 |
| ≤ 900px | 顶部标题、模块 chips、模块堆叠、缺口清单、readiness | 固定全屏抽屉 |
| ≤ 480px | 项目名收起，chips 换行，缺口清单压缩 | 全屏抽屉，关闭按钮常显 |

移动端工坊不渲染力导向图，改为“模块堆叠 + 缺口清单”。缺口清单的真实来源是模块 blockers：缺数据材料、缺环境变量、失败运行、待人工确认等；下方给出基于当前状态的下一步建议。这个块不是装饰性占位，而是让移动端在没有图的情况下仍能完成判断。

### 4.4 空态与边界

- 没有选中模块时，详情栏为空态，不显示假数据。
- 模块状态只有 `ready / attention / blocked` 三档，颜色和文案来自真实派生。
- readiness 不是学术质量结论；界面明确标注“平台评分 · 非学术质量判定”。
- 工坊只做前端装配，不写后端；刷新只重新取数，不改动任何项目对象。

## 5. 数据口径

所有数字只来自后端：

- `useBloomUnits` 提供一级卡片的摘要与状态。
- `useAtelierData` 派生工坊模块状态、readiness、环境缺失、失败运行、事实证据、报告数量。
- `UnitDetail` 与 `unitDetailParts` 是二级、三级共用的真实详情层。
- `parse_status` 兼容后端返回的 `parsed`，避免把已解析材料误显示为 0/2。
- 数据集模块同时统计数据材料与代码资产；摘要写“0 份数据 · 1 份代码资产”，不把代码资产伪装成数据材料。

已知契约偏差记录在 `docs/API_CONTRACT_STAGE4.md` 与实现注释中，不在 UI 层补造字段。

## 6. 运动与可访问性

- 不引入 framer-motion、GSAP、Three.js；只用 CSS transition + `requestAnimationFrame`。
- 动画只改 `transform / opacity / clip-path`，不改宽高和布局；拖动和视差合并到帧。
- 入场延迟按卡片顺序 90ms + order × 70ms；减少动态时立即到位。
- 所有可点击卡片是 `button`，展开面板有 `role=region` 与 `aria-label`；`Esc` 可收起。
- `prefers-reduced-motion: reduce` 下关闭入场与形变动画，直接显示最终态。
- 滚动区可用键盘聚焦，`tabIndex=0`；关闭按钮有 `aria-label=收拢`。
