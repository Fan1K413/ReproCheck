# ReproCheck 科研自动化工作流与智能实验助手 · 升级规格（第七阶段 / Stage 13）

## 1. 背景与边界

ReproCheck 已具备：复现规划 DAG、受控执行、日志记录、失败诊断、修复审核机制。
本次升级**不重复实现**上述能力，而是在其之上补齐"把科研人员提出的检查需求转化为
真正可执行、可追踪、可审核的科研工作流"的编排与闭环能力。

### 1.1 既有复用（不重写）

| 既有能力 | 复用点 |
| --- | --- |
| 复现规划 DAG / 依赖校验 | 编排引擎复用拓扑排序、循环依赖校验思路 |
| 受控执行 / 安全隔离后端门禁 | 实验执行节点复用 `ExecutionSandbox.sandbox_available()` 门禁 |
| 环境探测 | 恢复服务复用 `EnvDetector.detect()` |
| 确定性失败诊断 | 恢复服务复用 `classify_failure()` 分类与候选原因 |
| 审计轨迹 | 所有自动操作经 `record_trail` 落 `AuditTrail` |
| 事实/证据/指标模型 | 补证与助手直接读取既有 `ExtractedFact` / `EvidenceItem` / `ReproductionMetric` |
| 第十二阶段 ResearchTask | 协作待办项；本阶段 DAG 执行引擎与其并存，不互相替代 |

### 1.2 本次新增

- 多步骤任务编排引擎（依赖、前置条件、优先级、重试、暂停/恢复/取消、人工确认、历史）
- 证据缺口识别与补证闭环（缺口分类 → 补证任务 → 确认执行 → 证据回链）
- 失败智能恢复（诊断 → 检查 → 补丁提案 → 隔离副本测试 → 批准后应用，原始项目不动）
- 八类可复用科研任务模板（真实节点链，非空白表单）
- 自然语言科研任务助手（意图解析 → 定位项目/证据 → 建任务 → 执行 → 返回结果）

## 4. 模块设计

### 4.1 科研任务自动编排

- **多步骤编排**：工作流由节点 DAG 组成；创建时做拓扑排序、重复 key、未知依赖、循环依赖校验。
- **依赖分析**：节点 `depends_on`；后继节点在前置节点成功后才可调度；前置失败/取消/跳过按阻断处理。
- **前置条件自动检查**：节点声明所需材料（名称/类型）、所需事实、最少事实数、是否需要沙箱；
  不满足时节点置 `blocked` 并保留原因，不强行执行。
- **优先级**：就绪节点按优先级降序、拓扑序升序调度。
- **失败重试**：节点 `max_retries`；失败后可自动重试（计入 `retry_count`），耗尽后置 `failed`；
  手动重试仅允许对 `failed` 节点。
- **暂停 / 恢复 / 取消**：工作流级控制在节点边界生效；暂停后调度停止；恢复后重新推进；
  取消将未终结节点一并置 `cancelled`。
- **人工确认节点**：`needs_human_confirm` 或 `human_confirm` 类型节点到达后置
  `awaiting_confirmation`，批准放行 / 拒绝跳过；决策人与时间落库并写轨迹。
- **执行历史**：每次尝试独立 `NodeAttempt`，含日志摘录、错误码、耗时、资源约束。

### 4.2 科研实验自动补证

1. **找出缺失证据**：扫描事实，区分取值缺失、证据引用缺失、低置信度歧义。
2. **分析需要补充什么**：诊断记录缺失类型、现有取值、置信度、是否已有证据。
3. **可否从现有代码/配置提取**：存在代码/配置材料且字段为配置类 → `extractable_from_existing`。
4. **是否需要用户上传**：无相关材料 → `needs_upload`。
5. **是否需要重新执行实验**：指标/结果类主张且无复现指标 → `needs_rerun`。
6. **生成补证任务**：按缺口类别生成任务，标注所需上传物或重跑计划。
7. **用户确认后执行**：既有提取类确认后可执行；上传/重跑/人工类保持等待外部输入。
8. **证据回链**：新证据描述回链原始主张（`linked_claim_id`），缺口关闭。

### 4.3 失败后的智能恢复

- **识别失败类型**：复用确定性诊断分类。
- **定位日志**：原始日志落 `recovery_logs` 快照，方案记录引用。
- **环境/依赖/数据路径/资源检查**：环境画像、缺失依赖、失败数据材料、OOM/超时/路径错误模式与资源上限。
- **修复建议与补丁提案**：按失败类别给出建议；补丁提案含变更类型、目标文件、原始/提议内容、理由。
- **隔离副本测试**：材料快照复制到 `worktrees/<plan_id>/`；无安全后端时测试如实 `skipped`，
  有后端时复测由受控执行流程发起，不伪造通过。
- **批准后应用**：仅 `approved` 且测试通过（或显式同意跳过）可应用；
  **原始科研项目不被自动修改**，`original_preserved` 恒记录；写回受安全后端门禁约束。

### 4.4 科研任务模板（八类，真实节点链）

| 模板 key | 场景 | 节点链 |
| --- | --- | --- |
| `ml_paper_reproduction` | 机器学习论文复现 | 材料完整性 → 参数一致性 → 数据质量 → 环境依赖 → 复现实验(确认) → 指标对照 |
| `cv_experiment` | 计算机视觉实验 | 数据/标注检查 → 划分泄漏 → 配置核对 → 训练(确认) → 评测 → 图表核验 |
| `nlp_experiment` | NLP 模型实验 | 语料/分词 → 超参核对 → 分布泄漏 → 训练(确认) → 指标核对 |
| `ablation_study` | 消融实验 | 基线/变体清单 → 配置差异 → 逐变体对照 → 结论一致性 |
| `hyperparam_comparison` | 超参数对比 | 配置清单 → 取值一致性 → 分组指标对比 → 最优配置核验 |
| `dataset_quality` | 数据集质量检查 | 可达性 → 模式/编码 → 分布/泄漏 → 问题与补证建议 |
| `model_evaluation` | 模型评测 | 评测集/脚本 → 指标口径 → 指标复算对照 → 显著性核验 |
| `stats_verification` | 统计结果核验 | 设计核对 → 数值重算 → 显著性/容差 → 措辞一致性 |

### 4.5 科研任务自动化助手

- **解析意图**：确定性规则匹配七类意图（参数比对/证据检查/数据质量/评测/消融/超参/统计核验），
  提取规范字段 key；预留 LLM schema 兜底扩展点。
- **找到对应项目**：显式指定则校验访问权；未指定且仅一个可访问项目时自动定位；多项目则返回
  `needs_project_selection`，不跨项目执行。
- **找到相关证据**：按字段匹配既有事实与材料，返回证据提示清单。
- **创建任务并执行检查**：生成单节点工作流并启动；高风险表述（重跑/训练/改代码/应用补丁）
  节点置人工确认。
- **返回结果**：工作流视图（节点状态、尝试、事件）+ 解析意图 + 证据提示。

### 4.6 工程真实性约束

- 状态真实：所有节点/工作流状态落库，前端轮询读取，不模拟完成进度。
- 日志真实：每次尝试记录真实日志摘录、耗时与错误；失败现场随 attempt 保留。
- 失败留现场：错误码、错误信息、失败类别、日志快照不被后续重试覆盖。
- 审计轨迹：创建、启动、暂停、恢复、取消、重试、确认、补证、恢复审批与应用均写 `AuditTrail`。
- 幂等与恢复：`idem_key` 复用活跃工作流；心跳过期节点由 `recover_stale` 回收；待确认节点不回收。
- 资源限制：并发上限、节点超时、自动重试次数受配置约束；尝试记录资源约束快照。

## 6. 验收标准

1. 模板建链后 DAG 校验通过；无数据的检查节点返回 `insufficient_data/skipped`，不伪造结论。
2. 前置条件缺失时节点 `blocked` 且原因可读；满足后可被调度。
3. 高风险节点停在 `awaiting_confirmation`，未批准不执行。
4. 失败节点保留全部 attempt 现场；重试产生新 attempt，历史不被覆盖。
5. 补证缺口可被扫描、分类、生成任务；确认后执行并回链主张；上传/重跑类不自动执行。
6. 恢复方案生成隔离副本；无后端时测试 `skipped` 并写明原因；未批准不应用；原始项目保留。
7. 助手可把"检查论文学习率与代码实际学习率是否一致"解析为参数比对任务并执行。
8. 所有状态变更可在工作流事件与审计轨迹中回溯。
