## 二、优先级

- **P0（直接关系科研结论可信度或核心可用性）**：U1 统一可信结论层、U2 能力驾驶舱。
- **P1（显著提升效率/可信度）**：U3 标准证据包、U4 README/引导、U6 评分卡。
- **P2（有价值，后续迭代）**：U8 事件会话、U5 代码版本真实关联、U7 外部导入。

## 三、本阶段落地选择（不超过 3 项，用户第七步要求）

**选择 U1 + U2 + U4**，理由：
1. 四组调研共同指向"引擎强、驾驶舱弱"：U2 让已通过测试的后端能力真正可达（D 组问题二 P0）；U4 修复 README 失信（D 组问题一 P0）。
2. U1 是科研可信度核心且四组共识（ACM 解耦分层 + 结论五态 + C 组"独立核对层"定位 + D 组问题四状态割裂），且能用**聚合层**实现，不推翻现有子系统（兼容现有架构）。
3. U3/U5/U7 依赖外部标准/网络/沙箱，在"不执行第三方代码、不购买服务、不破坏稳定"约束下风险高于收益；列入 P1/P2 并写清后续条件。
4. 三项合计可在一个工作区内以增量方式完成，均可独立回滚（对应 tag `stage9-baseline`）。

## 四、不做什么（明确边界）

- 不引入微服务/多智能体/复杂框架（用户明确禁止）。
- 不重构 200 项测试覆盖的现有引擎；U1 采用新增聚合 API + 前端统一展示，旧端点保留。
- 不执行上传代码、不购买服务、不伪造论文结果或调研数据。
- 不宣称 ACM 认证——只写"参考 ACM v1.1 框架设计自检项"（B 组合规红线）。

## 五、验收口径（冻结，实施前确认）

1. U1：新增统一结论 API，输出五态 + ACM 三维；前端至少一处主流程用同一模型展示；有测试断言状态映射；旧状态枚举不被删除（兼容）。
2. U2：6 项能力中至少 4 项有可点击前端入口并真实调用 API（不是静态按钮）；typecheck/build 通过。
3. U4：README 与真实状态一致，含"能力—入口—状态"表；不出现"第一阶段"过时表述。
4. 全量后端测试 ≥205 passed 无新增失败；每次迁移有回滚路径；临时脚本清理。
