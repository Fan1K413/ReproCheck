## 1. 结论摘要

本轮共记录 **18 项**影响“第一次使用、知道下一步、看懂术语、配置 API、核对真实状态”的问题：

- 已修复并验证：**16 项**
- 明确未解决：**2 项**（U-17 服务端加密密钥缺失、U-18 外部真实用户测试未组织）

其中对“难用”贡献最大的不是功能缺失，而是四个断点：

1. 首次进入看到的是 9 个专业入口，而不是“我能做什么”。
2. 完成材料或报告后，页面不告诉用户下一步去哪里。
3. API 页面把服务商、协议、端点、能力矩阵同时铺开，且错误信息不够任务化。
4. 同一个概念在不同页面有不同名字（DAG/规划、解析/事实、材料/档案），新用户无法建立稳定心智模型。

## 3. 仍存在但已记录的风险

- **P1 性能风险**：`NextStepCard` 在项目页会并行读取材料、任务、事实、规划、环境、运行、报告 7 类数据。当前接口均 200，但项目数据量大时需要缓存或聚合接口。当前未优化，避免为了“下一步”引入新的假状态。
- **P2 信息密度**：五步向导第 1 步仍列出 11 家服务商，首次使用者可能不知道选哪家。已在卡片显示“常用模型数量 / 是否自填地址”，但没有基于用户已有密钥做推荐。
- **P2 窄屏操作**：390 宽度工作台顶栏只显示图标（“我想做什么/中文手册/帮助”无文字标签），依赖 `aria-label`。功能可用，但首次使用者可能不知道每个图标是什么。未解决。
- **P2 成功路径未验**：因 `MODEL_CREDENTIAL_KEY` 缺失，真实 API 的“测试通过 → 保存成功”链路未能在本机完成。测试接口可在无加密密钥时真实调用；保存仍需管理员配置。详见 `USABILITY_OPEN_ISSUES.md`。
