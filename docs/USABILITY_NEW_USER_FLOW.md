# ReproCheck 新用户操作流程

日期：2026-11-24  
适用范围：第一次使用 ReproCheck 的科研人员、研究生、项目负责人；不需要编程基础。  
原则：每个阶段只回答一个问题；复杂配置不删除，只折叠到第二层；所有“下一步”只根据真实数据生成。

## 1. 首次进入：先选目标，不看图标墙

首次访问（浏览器没有 `rc:onboarding:v1`）不会直接显示 9 个专业入口，而是：

1. **欢迎页**：说明“ReproCheck 会带你把论文、数据、代码和实验结果串起来”，提供六张能力卡和“下一步：选择我想做的事”。
2. **目标页**：五个目标选项：
   - 我想复现一篇论文 → 直接进入 `/start/reproduce`；
   - 我想管理已有项目 → 进入 `/projects`；
   - 我想检查一次实验结果 → 选择项目后进入结果对照；
   - 我想生成或查看报告 → 选择项目后进入审计报告；
   - 我还不知道怎么用，带我看看 → 一分钟四步讲解，可继续进入引导或先进入工作台。
3. **项目/学习分支**：选择真实项目，或新建项目；不预填假项目、不预填假论文。
4. **跳过**：任何时候可点“先跳过，直接进入工作台”，状态保存为 `skipped`；刷新不会再次弹出。

### 状态与回流

| 状态 | 行为 |
|---|---|
| 无 `rc:onboarding:v1` | 首次进入欢迎页 |
| `rc:onboarding:v1=done` | 直接进入径向工作台 |
| `rc:onboarding:v1=skipped` | 直接进入径向工作台 |
| 工作台点“我想做什么” | 直接进入目标页，不再看欢迎页 |
| 访问 `/?what=1` | 从其他页面回到工作台并直接打开目标页 |

## 2. 返回用户：保留径向工作台，增加任务入口

返回用户看到的是已经验收的深墨紫径向工作台，保留品牌、九入口、花瓣二级卡和既有数据。

顶部新增三个轻入口：

- **我想做什么**：重开任务选择；
- **中文手册**：进入 `/manual`；
- **使用帮助**：在当前页打开帮助抽屉。

这不是把工作台改成 WorkBuddy 的聊天界面；而是在保留专业空间感的前提下，给不知道从哪开始的人一个“绕开图标墙”的路径。

## 3. 四步复现引导（`/start/reproduce`）

### 第 0 步：选择项目

- 列出当前账号有权限的真实项目（最多 6 个）；
- 也可以新建项目：项目名必填；论文标题/领域可空，空值写“待补充”，不编造；
- 选中后自动写回 URL 的 `project`，刷新可恢复。

### 第 1 步：添加论文

- 接受 PDF/TXT/MD；推荐 PDF；
- 上传成功显示服务器返回的文件名，并自动进入下一步；
- 没有论文可以跳过，报告会记录缺项；
- 下方说明“论文进入材料清单，之后可以开始解析”。

### 第 2 步：补充数据

- 接受 CSV/XLSX；
- 上传真实文件，不做前端假进度；
- 没有数据可以跳过，报告会记录“数据缺失”限制。

### 第 3 步：登记代码

- 可以粘贴 GitHub/GitLab/Gitee 仓库地址，填写一个容易认的名字；
- 后端只登记 URL，不下载、不执行；
- 也可以上传 zip/py/ipynb；
- 成功后材料类型显示“代码仓库链接”，材料页只提供“打开仓库”，不提供“解析/下载”。

### 第 4 步：准备实验

- 读取项目真实材料，显示论文/数据/代码哪些已有；
- 每项显示“查看”或“去补充”；
- 显示“材料完整度 x/3 类核心材料”；
- 显示 AI 是否已连接；没有连接也可以进入复现总览；
- 主按钮“进入复现工作台”，次按钮“先看完整材料清单”。

## 4. 项目内主流程

| 阶段 | 页面 | 用户要做什么 | 真实判断下一步的依据 |
|---|---|---|---|
| 建项目 | `/projects/new` | 起名、填论文标题（可空） | 项目是否存在 |
| 加材料 | `/projects/:id/materials` | 上传论文、数据、代码或登记仓库 | `GET /materials` 的类型与数量 |
| 读论文 | `/projects/:id/materials` | 对论文发起解析 | `GET /parse-tasks` 状态 |
| 看事实 | `/projects/:id/facts` | 逐条核对事实与原文 | `GET /facts/summary` |
| 拆步骤 | `/projects/:id/reproduction` | 创建复现规划/步骤清单 | `GET /reproductions/plans` 数量 |
| 对实验环境 | `/projects/:id/reproduction/environment` | 记录 Python、依赖、系统 | `GET /reproductions/environments` 数量 |
| 运行 | `/projects/:id/reproduction` | 执行或记录一次真实运行 | `GET /reproductions/runs` 数量 |
| 对照 | `/projects/:id/reproduction/comparison` | 论文指标 vs 复现结果 | `GET /reproductions/metric-comparisons` |
| 出报告 | `/projects/:id/reproduction/reports` | 生成/查看审计报告 | `GET /reproductions/reports` 数量 |
| 复核 | 报告/事实/证据 | 检查每条结论是否有证据 | 真实报告与证据数量 |

页面顶部的 `NextStepCard` 会在上述每一步给出一句判断和两个动作。它不是固定文案：没有论文时提示“第一步：添加论文”；没有完成解析时提示“让系统读一遍论文”；有报告时提示“报告已生成，做最后复核”。

## 5. AI 连接流程（可选）

AI 是增强，不是使用前提。没有 API 密钥也能管理项目、材料、对照和报告。

默认路径：`/settings/models?tab=setup` → 五步向导：

1. 选择服务商（11 家真实适配器）；
2. 粘贴 API 密钥；
3. 选择模型（服务商默认模型或手动填写）；
4. 真实测试连接（临时凭据只在内存中，不落库）；
5. 测试通过后保存为默认 AI 助手。

高级设置（服务地址、超时、最大输出、温度）默认折叠。失败时显示普通中文原因，技术详情可展开；失败状态不显示保存按钮。

系统级状态在 `/settings/llm`，只用于排错，不承担个人密钥配置。

## 6. 出错时的统一处理顺序

1. 先看页面内红色提示，确认是权限、网络、文件大小还是服务商错误；
2. 打开当前页“使用帮助”，看“出错怎么办”；
3. 仍无法解决时，打开 `/manual#errors` 对照错误表；
4. 若是 API 保存失败且提示 `MODEL_CREDENTIAL_KEY`，联系管理员配置，不要把密钥发给别人或写进材料。
