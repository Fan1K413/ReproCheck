# 未解决问题与风险清单

日期：2026-11-24  
原则：未验证、未配置、未完成的事项必须显式记录，不能写成“已完成”。

## P0：真实后端保存 AI 配置仍缺少加密密钥

**现象**

- 真实后端（`127.0.0.1:8000`）没有配置 `MODEL_CREDENTIAL_KEY`；
- 本轮已修改 `test-draft`：临时测试凭据只放在进程内存里，不再要求 Fernet 加密。2026-11-24 20:14 在重启后的 8000 上用无效密钥实测：HTTP 200、`status=auth_failed`、`error_code=LLM_INVALID_KEY`、139ms；
- 8001 也在无 `MODEL_CREDENTIAL_KEY` 的干净进程中复验通过（209ms），说明“测试不需要持久化密钥”的修复是真的；
- 但 `POST /model-setup` 保存凭据时必须使用 `MODEL_CREDENTIAL_KEY`；未配置时保存会失败，前端显示明确中文说明。

**影响**

- 用户可以完成真实连接测试，但无法在未配置密钥的环境保存 AI 配置；
- “测试成功 → 保存成功”链路在本机仍未验证；
- 不能把该状态说成“API 向导已完全走通”。

**建议处理**

- 管理员在部署环境设置一个独立的 32 字节随机密钥（Fernet key 或长口令），不要复用 `JWT_SECRET`；
- 配置后重启后端，重新跑五步向导，用真实有效密钥完成一次成功保存；
- 把该配置写入部署清单，不要把密钥写进 Git、文档、截图或聊天。

## P0：外部真实用户测试未组织

**现象**

- 本轮仅有开发者自动化走查与真实接口测试；
- 没有外部真实用户独立使用，因此不能写“真实用户测试通过”；
- 招募来源、时间、样本数均由用户/团队决定，不能由我代填。

**影响**

- 可用性缺陷的“首次理解成本”无法用真实用户行为证明；
- 当前结论只能证明“页面可操作、接口真实、无脚本错误”，不能证明“普通人第一次就会用”。

**建议处理**

- 招募 3–5 名未使用过 ReproCheck 的科研人员/研究生；
- 用 `docs/USABILITY_REAL_USER_TEST_REPORT.md` 的 5 个任务脚本，记录完成率、耗时、卡点、原话；
- 完成后补充样本、日期、任务结果；不要把开发者走查冒充用户测试。

## P1：真实 API 成功路径未验证

- 缺少有效服务商 API 密钥；仅验证了无效密钥的真实失败路径（8000：`auth_failed`，139ms，HTTP 200；8001：209ms，HTTP 200）。
- 8000 与 8001 都已在没有 `MODEL_CREDENTIAL_KEY` 的进程中验证了临时测试路径；没有任何真实有效密钥，不允许伪造成功。
- 配置 `MODEL_CREDENTIAL_KEY` 与真实密钥后，必须补：
  - 测试成功；
  - 保存成功；
  - 刷新后默认模型真实存在；
  - 模型列表只显示脱敏提示；
  - 重启后仍能解密并调用。

## P1：NextStepCard 读取 7 类接口，可能放大项目页开销

- 每个项目页会并行读取材料、任务、事实、规划、环境、运行、报告；
- 当前真实数据量小，接口均 200，页面无错误；
- 大数据量/慢网络下可能拖慢首屏；
- 未做聚合接口或缓存，避免为了“下一步”引入假状态。

建议：后续把 7 类计数聚合成一个 `GET /projects/:id/next-step`，并在前端做 15–30 秒缓存；本轮不擅自改后端业务。
