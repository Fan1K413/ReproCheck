## 4. 外部用户测试方案（待执行）

### 4.1 样本与组织

- 样本：3–5 名未使用过 ReproCheck 的科研人员、研究生或实验室助理；至少 2 名非计算机专业。
- 排除：本项目开发者、看过本轮设计文档的人、参与实现的人。
- 单场时长：30–40 分钟；一对一；主持人只读任务，不教操作。
- 环境：测试专用项目与样例材料，不使用参与者自己的未发表数据；API 任务只使用无效测试字符串，禁止收集真实密钥。
- 记录：经口头与书面同意后录屏/录音；报告匿名化为 U01–U05，不写真实姓名、单位、邮箱。
- 样本量说明：3–5 人用于发现高严重度可用性缺陷，不用于统计显著性；不得把 5 人结果外推为“所有用户都通过”。

### 4.2 五个任务脚本

每个任务开始前只给一句目标，不念菜单路径；观察者记录完成、耗时、提示次数、卡点原话。

**T1 第一次进入：找到开始方式**

- 起始：清空 `rc:onboarding:v1`，已登录，打开 `/`。
- 任务话术：“你是第一次用，请从打开软件开始，走到可以添加论文的那一步。”
- 成功标准：不靠提示，完成引导并进入 `/start/reproduce?step=1` 或项目选择页。
- 记录：是否理解“先告诉我你要做什么”；是否误点“跳过”；首次点击前的犹豫时间。

**T2 四步复现：准备论文、数据、代码**

- 起始：测试专用空项目；准备一份 3 页样例 PDF 与公开仓库 `https://github.com/octocat/Hello-World`。
- 任务话术：“把这个项目的论文、数据和代码各放好；没有的可以跳过。做完后告诉我项目还缺什么。”
- 成功标准：至少完成 2 类材料；第 4 步能说出真实缺项，不把“已登记链接”误认为“代码已运行”。
- 记录：上传失败时能否恢复；是否理解“只登记、不下载”；是否发现“换项目”。

**T3 API 五步：粘贴一个无效密钥**

- 起始：`/settings/models?tab=setup`；提供无效字符串 `sk-invalid-user-test`，明确说明不是真实密钥。
- 任务话术：“把 DeepSeek 接进来。先用这个无效密钥试，看看软件会怎么提示。”
- 成功标准：独立走到第 4 步并触发真实失败；能复述“密钥无效/检查权限”；知道失败时不能保存。
- 记录：第 2 步是否知道密钥是什么；第 3 步是否理解模型名；失败后第一反应；是否打开技术详情。

**T4 报告之后：找到下一步**

- 起始：已有报告的测试项目，打开材料页或项目页。
- 任务话术：“报告已经有了。你现在要交付，接下来会做什么？”
- 成功标准：能指出顶部“报告已生成，做最后复核”并打开审计报告或证据检查；不要求记住菜单名。
- 记录：是否看见下一步条；是否把“打开审计报告”和“检查证据”区分开。

**T5 手册与术语：查“证据”**

- 起始：`/manual`。
- 任务话术：“用页面里的手册查一下‘证据’是什么意思，并告诉我它和‘结论’有什么不同。”
- 成功标准：30 秒内筛出相关章节，能用自己的话解释“证据是原文/定位，结论要基于证据”。
- 记录：是否发现目录筛选；是否使用术语悬停；是否迷失在 11 章目录。

### 4.4 判定规则

- **通过**：至少 4/5 参与者在 T1、T2、T4、T5 中无需关键提示完成；5/5 能在 T3 说出“密钥无效/权限问题”，且无人误以为失败也能保存。
- **有条件通过**：核心任务完成，但 2 人以上在同一处卡住超过 2 分钟；需要按卡点修复后复测。
- **不通过**：T1 或 T4 有 2 人以上无法完成；或有人因提示误删数据、误传真实密钥、误以为代码被执行。
- 任何 P0 级误解（把未验证写成已验证、把链接登记当成复现成功）单独记为阻断，不因总体完成率高而放过。
