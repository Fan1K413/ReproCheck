# ReproCheck 第六阶段 · 用户访谈提纲

> 状态：**提纲已建立，访谈尚未执行**。禁止将任何预设回答写成真实访谈记录。
> 适用：45–60 分钟半结构化访谈，对象为 ML/CS/DS 领域科研人员。
> 记录规范：每场访谈记录编号、日期、角色、是否录音（需单独同意）、关键引述（匿名化）、观察到的矛盾点。

## 0. 开场（5 分钟）

- 自我介绍与调研目的：改进科研复现审计工具，不是推销产品。
- 知情同意：匿名化、可退出、录音单独征得同意。
- 暖场：请简述您最近一次复现论文的经历（论文方向、是否成功、花了多久）。

## 1. 材料管理与工作流（10 分钟）

1. 您手头一篇要复现的论文，通常配套哪些材料？（代码仓库、补充材料、配置、数据、README、issue 区……）
2. 这些材料分别存在哪里？多久整理一次？找某个参数时通常翻几个地方？
3. 请回忆最近一次「找一个参数找了很久」的经历：找的是什么、最后在哪找到、花了多久？
4. 实验记录记在哪里？（实验跟踪工具 / 表格 / 笔记 / 不记）记哪些字段？事后能还原当时环境吗？

**追问要点**：跨文件寻找依据的真实频率；记录不完整导致的实际后果。

## 2. 复现痛点与不一致经历（15 分钟）

5. 复现全流程中，哪一步最耗时？哪一步最容易出错？两者是同一步吗？
6. 是否遇到过论文写的参数和代码实际用的不一样？请具体讲一次：怎么发现的、差异是什么、最后以谁为准？
7. 默认参数覆盖问题：代码里 argparse 默认值、配置文件、命令行覆盖、论文描述，您如何确认「实际生效值」？
8. 环境复现（Python/CUDA/依赖版本）踩过什么坑？论文里写的环境信息够用吗？
9. 结果对不上时，您如何排查？通常花多久？放弃过吗？

**追问要点**：不一致的真实频率与代价；「实际生效值」确认难度；对自动比对的期望与怀疑。

## 3. 协作与审核（10 分钟）

10. 您的复现是一个人做还是多人做？多人时如何分工、如何同步进度？
11. （导师/负责人）您如何检查学生的复现质量？看什么材料？发现过学生记录与结果不符吗？
12. （学生）导师审核您的复现时，您需要准备什么？准备过程耗时吗？
13. 如果平台记录「谁上传了材料、谁改了结论、谁批准了修复」，对您有价值吗？还是负担？
14. 评论/讨论希望挂在什么对象上？（某条审计问题、某段证据、某个复现任务）为什么？

**追问要点**：协作是真实高频还是偶发；审核的证据需求；对操作留痕的接受度。

## 4. 工具链与集成（8 分钟）

15. 日常用哪些工具？（GitHub/GitLab/Gitee、Jupyter、文献管理、实验跟踪、云计算）
16. 论文引用的代码版本和仓库当前版本不一致时，您怎么处理？关注 commit/tag 吗？
17. Notebook 在您的工作流里是什么角色？（正式实验 / 草稿 / 教学）需要保留 cell 执行顺序和输出吗？
18. 如果审计平台能连接您的仓库，您愿意授权吗？公开仓库和私有仓库有区别吗？顾虑是什么？

## 5. 信任、隐私与采纳意愿（8 分钟）

19. 一个工具告诉您「论文和代码参数冲突」，您信吗？需要看到什么才信？
20. 您能区分「AI 推测」和「程序验证」吗？如果工具混在一起标注，您怎么看？
21. 上传未发表论文/私有代码，您的底线是什么？（本地部署 / 脱敏 / 不用于训练 / 可删除 / 机构合规）
22. 什么情况下您会把这个工具推荐给学生或同事？什么情况下会劝退？
23. 如果只能选一个功能先做，您选哪个？为什么？

## 6. 收尾（4 分钟）

- 总结受访者提到的前三痛点，请其确认或纠正。
- 是否愿意参与后续试点？试点需要实验室 PI 同意，流程告知。
- 感谢与后续联系方式。

## 分析规范

- 每场访谈后 24 小时内完成纪要；双人独立编码主题，分歧讨论解决。
- 区分「自我报告频率」与「观察到的行为」；试点观察优先于问卷自报。
- 样本量与招募偏差如实写入分析报告；不足以下结论时明确写「证据不足」。
