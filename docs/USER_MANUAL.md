# ReproCheck 中文使用手册

版本：2026-11-24  
适用对象：第一次使用 ReproCheck 的科研人员、研究生、项目负责人和复核人员。  
原则：只描述当前真实具备的功能；没有的功能不写，未验证的状态不写成已完成。

---

## 0. 打开与登录

1. 启动后端（FastAPI，默认 `127.0.0.1:8000`）。
2. 启动前端（Vite，默认 `127.0.0.1:5173`）。
3. 浏览器打开前端地址，使用项目负责人提供的账号登录。
4. 登录后如果看到“不用先学软件，先告诉我你要做什么”，说明你是第一次进入；按第 1 章开始即可。

> 不要把登录口令、API 密钥或未脱敏数据写进项目材料、代码仓库或截图。

---

## 1. 五分钟开始：先做一件小事

第一次打开，不要先研究所有菜单。按顺序只做当前需要的一步：

1. 在工作台选择“我想复现一篇论文”，或直接打开“四步复现引导”。
2. 选择已有项目，或新建一个项目。项目名只要你自己认得出即可。
3. 上传论文 PDF。数据和代码没有也能先继续。
4. 进入复现总览，跟着页面顶部的“下一步”提示继续。

完成到这一步，你已经有了一次真实可继续的项目，而不是一个空演示页面。

### 你不需要先理解的事

- 不需要懂编程。代码仓库链接只登记，不会在你的电脑上自动执行。
- 不需要先买 AI 服务。API 配置是可选增强；项目、材料、对照和报告仍可使用。
- 不需要一次把所有材料找齐。缺项会被如实记录，不会被伪造补齐。

---

## 2. 四步复现引导

入口：左侧“四步复现引导”，或工作台“我想复现一篇论文”。

### 第 0 步：选择或新建项目

- 页面只列出你当前有权限打开的真实项目。
- 已有项目直接点选；没有就点“新建一个项目”。
- 新建时项目名必填；论文标题和研究领域可以空着，页面会写“待补充”，不会替你编造。
- 选中项目后，地址栏会带上项目与步骤，刷新可恢复。

### 第 1 步：添加论文

- 要准备：论文 PDF；TXT/MD 也可以，但 PDF 最稳妥。
- 做完得到：项目材料清单里出现论文，之后可以开始解析。
- 没有论文：可以跳过；报告会记录缺项，不会补假数据。

### 第 2 步：补充数据

- 要准备：CSV / Excel 文件；多个文件可以逐个上传。
- 做完得到：项目里多出数据文件与来源记录。
- 没有数据：可以跳过；报告会记录“数据缺失”的限制。

### 第 3 步：登记代码

- 要准备：GitHub / GitLab / Gitee 等仓库网页链接，或 zip/py/ipynb 代码文件。
- 仓库地址只登记，不下载、不执行；材料页只显示“打开仓库”。
- 做完得到：材料清单里出现“代码仓库链接”。
- 没有代码：可以跳过；报告会记录“代码缺失”。

### 第 4 步：准备实验

- 系统按项目真实材料核对论文/数据/代码是否已有，不预估进度。
- 每项可以“查看”或“去补充”。
- 显示 `x/3 类核心材料` 完整度。
- AI 是否连接也会显示；没有连接不影响进入复现总览。
- 主按钮“进入复现工作台”，次按钮“先看完整材料清单”。

> 跳过不是失败。系统只会在报告和下一步提示里记录“这项还缺”，不会把空白当成已完成。

## 3. 项目与材料

### 项目是什么

项目是总文件夹；材料是项目里的论文、数据、代码和配置。一个项目只放同一篇论文的复现内容，最容易管理。

### 新建项目

1. 从“项目档案”点“新建项目”，或从四步引导里新建。
2. 项目名用你能认出的名字，例如“ResNet 图像分类复现”。
3. 论文标题和领域不确定时可以留空；系统写“待补充”。
4. 创建成功后，先上传论文，再考虑数据与代码。

### 上传材料

- **论文**：推荐 PDF。上传后还需要“解析”，系统才会尝试读出原文块和事实。
- **数据**：CSV / Excel。多个文件逐个上传；文件是否敏感由你判断。
- **代码**：可以登记仓库链接，也可以上传 zip / py / ipynb。当前不会自动执行代码。
- **说明文件**：README/TXT 可帮助系统理解项目，但仍需人工复核。

材料页的“上传材料”区支持拖拽和选择文件；上传状态与解析状态均由服务器返回，前端不伪造进度。

### 材料详情

点击材料卡可展开右侧详情：

- 文件大小、上传时间、文本块数、事实数、SHA-256；
- 解析状态与错误信息；
- 代码仓库链接的“打开仓库”；
- 普通材料的“解析 / 下载 / 删除”；
- 关联事实和证据。

不要把 API 密钥、身份证件或未脱敏患者数据上传到不需要它的项目。

## 4. 解析、事实与证据

### 解析是什么

解析是把 PDF 变成可搜索的文字块；事实抽取是从文字块里找出数据集、方法、指标等条目。**事实不是结论**，只是待核对的线索。

### 怎样检查读得对不对

1. 打开材料详情，先看解析状态与告警。
2. 再看原文预览，确认文字没有乱码或漏页。
3. 打开“科研事实”，逐条检查是否带原文位置。
4. 没有证据的条目不要直接写进报告；标为待复核或补充材料。

### 证据关系图是什么

它把事实和原文块连起来。图是空的，说明还没有可用的证据，不是系统故障。点节点可以回到来源。

### 什么时候算“读完”

不是“任务状态变成完成”就算读完。至少要确认：

- 原文没有明显缺页/乱码；
- 关键事实能指回原文；
- 互相矛盾的事实被记录，而不是被静默合并。

## 5. 步骤清单、实验环境与运行

### 步骤清单（原“复现规划 / DAG”）

复现步骤清单是一条任务清单，不是一段自动脚本。每条任务应该写明做什么、依赖什么、需要谁确认。

建议顺序：

1. 在复现总览创建手动规划。
2. 补齐任务和依赖；不确定的步骤标成需要人工确认。
3. 记录实验环境：Python、依赖包、操作系统和关键硬件。
4. 检查权限与安全策略后再启动运行。
5. 失败时保留日志和错误，不要用“重试到成功”掩盖问题。

### 实验环境

包括：

- Python / 解释器版本；
- 依赖包与版本（如 requirements.txt）；
- 操作系统与关键硬件；
- 必要的随机种子、数据划分与环境变量。

环境不同，结果可能不同；不要只记录“能跑”，要记录“在什么环境跑”。

### 运行记录

- 运行可能成功、失败或被安全策略阻止。
- 记录开始与结束时间、当前阶段、输出和错误。
- 如果后端没有启用安全执行环境，系统会阻止运行并说明原因。这是保护措施，不是让你找办法绕过。
- 成功也不等于论文结论正确；还需要结果对照和证据检查。

---

## 6. 结果对照、验证与报告

### 结果对照

把论文报告的指标与你的真实运行结果放在一起；关注指标、误差和差异原因。

**结果不同，不一定是论文错。** 环境版本、数据划分、随机种子、代码实现都可能造成差异。先记录差异，再分析原因；不要直接下结论。

### 项目验证

按证据覆盖情况汇总结论。没有证据的结论应保留为“未验证/证据不足”，不能自动升级为“已证实”。

### 审计报告

报告前的最低检查：

- 每条关键结论都有证据或真实运行记录；
- 没有把“未验证”“证据不足”写成“已证实”；
- 数据、代码或环境缺失已写进限制，而不是隐藏；
- 报告中的 AI 生成内容经过人工核对。

报告可以导出，但不应把“跑过”当成“结论正确”。

## 7. 连接 AI 助手（可选）

AI 服务是可选增强。它帮助你整理论文与排查问题，但不能代替证据和人工判断。

### 五步向导

入口：左侧“连接 AI 助手”，或直接打开 `/settings/models?tab=setup`。

1. **选择服务商**：列表来自后端真实适配器，不要假设所有厂商都已支持。
2. **输入密钥**：在服务商控制台创建 API Key，粘贴到这里；浏览器不保存明文，页面不回显。
3. **确认模型**：先用服务商提供的常用模型；不确定时不要手填奇怪名称。
4. **测试连接**：系统用你的密钥真实调用一次，不是前端假装成功。
5. **保存**：测试通过才允许保存；保存后设为默认模型。

高级设置（服务地址、超时、最大输出、温度）默认折叠，通常不用改。OpenAI 兼容服务需要在第 2 步填写服务地址。

### 常见概念

- **API 密钥**：服务商给你的一把“钥匙”，只给 ReproCheck 用。
- **模型**：真正读文字、给建议的 AI 程序。
- **服务地址**：AI 服务所在网址。一般自动填好，只有自建服务才改。
- **Token**：服务商计费和限流的计量单位，不是密码。

### 失败怎么办

向导会先显示普通中文原因（如“密钥没有通过验证”），技术详情折叠在下方。失败时不会出现保存按钮。

如果提示“服务器没有配置模型凭据加密密钥（MODEL_CREDENTIAL_KEY）”：这是管理员配置问题，不是你的密钥错。请联系管理员；你的密钥没有被发送或写入数据库。

**不要把密钥写进论文、代码仓库、聊天截图或工单。怀疑泄露时，立刻到服务商控制台撤销并重建。**

### 系统 AI 状态

`/settings/llm` 是系统默认服务的状态与排错页，不是你个人密钥的配置页。需要配置自己的模型时，回到五步向导。

## 8. 团队与权限

- **组织**管理成员与共享空间；**项目团队**决定谁能打开具体项目。
- 负责人可管理项目；研究员可处理材料与规划；复核员侧重检查；观察者通常只能看。
- 页面隐藏按钮不等于后端没有校验；真正的权限由后端执行。
- 邀请成员时使用对方登录邮箱。加入组织后，还需要加入具体项目团队，才能看到项目内容。
- 没有权限时页面会提示“无权访问”；不要反复重试，联系项目负责人添加权限。

## 9. 术语词典

页面中带下划线的术语可悬停/聚焦查看解释。完整表见 `docs/USABILITY_GLOSSARY.md`，这里列出最常用的 12 个：

| 术语 | 一句话解释 |
|---|---|
| 科研复现 | 照着论文再做一遍实验，看看结论能不能站得住。 |
| 论文 | 你要核对的那篇研究报告，通常是 PDF。 |
| 数据集 | 论文实验所用的原始数据或表格。 |
| 代码仓库 | 作者存放代码的网页地址；只登记，不自动运行。 |
| 实验环境 | 跑实验时电脑里的软件和版本组合。 |
| 软件依赖 | 实验运行前必须安装的软件包。 |
| API 密钥 | 服务商发给你的一串访问凭证，不能泄露。 |
| 模型 | 实际帮你阅读和整理内容的 AI 程序。 |
| 证据 | 能指回论文原文的依据。 |
| 科研事实 | 从论文中抽出的一条可核对信息。 |
| 复现步骤清单 | 把复现拆成可检查的步骤，不是自动脚本。 |
| 审计报告 | 把过程、证据和结论整理成可交付文档。 |

## 10. 常见错误

| 现象 | 先做什么 | 不要做什么 |
|---|---|---|
| 上传失败 | 检查文件类型、大小和网络；页面会显示后端具体原因 | 不要连续点击上传 |
| 解析一直排队 | 后台可能在处理其他任务或服务未启动；先刷新，再查后端日志 | 不要重复发起多个解析 |
| 事实为空 | 通常是没有完成解析或解析失败；先看任务状态，再回材料详情 | 不要把空事实当“论文没问题” |
| AI 测试失败 | 按向导普通中文提示处理：密钥、模型、网络或地址 | 不要跳过测试直接保存 |
| 保存 AI 配置失败并提示 `MODEL_CREDENTIAL_KEY` | 联系管理员配置加密密钥 | 不要改代码把密钥存明文 |
| 运行按钮是灰的 | 安全沙箱未启用，或角色没有执行权限 | 不要尝试绕过安全策略 |
| 报告内容空 | 先确认已有材料、事实和运行 | 报告不会用假数据填充章节 |
| 材料列表空白 | 看页面顶部错误；确认后端启动、项目权限正确 | 不要以为是“系统没有功能” |

更细的排错顺序：

1. 看当前页红色提示；
2. 打开当前页“使用帮助”的“出错怎么办”；
3. 打开本手册第 10 章；
4. 仍无法解决时，记录请求 ID、时间和页面路径，交给管理员；不要粘贴密钥。

## 11. 当前边界：这些事 ReproCheck 现在不会替你假装

- 不会自动下载或执行代码仓库；只登记地址。
- 没有安全执行环境时，不会假装运行成功。
- AI 没配置、额度不足或服务不可用时，不会用模拟回答冒充真实结果。
- 不会把“未验证”自动改成“已验证”；证据不足会保留。
- 不会替你在服务商处开通账号或购买额度。
- 当前界面没有项目删除与项目字段编辑入口；如需清理请联系管理员。
- 当前真实后端若未配置 `MODEL_CREDENTIAL_KEY`，API 连接可以测试，但不能安全保存；这是环境配置限制，不是前端假装失败。

这份手册对应本机当前版本。若页面与手册不一致，以真实页面和接口返回为准，并请反馈。
