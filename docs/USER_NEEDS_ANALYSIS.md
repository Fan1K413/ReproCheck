## 2. 需求分层（基于假设，待验证）

### 2.1 单人核心流程（已实现，第五阶段前）
上传 → 解析 → 事实抽取 → 跨材料比对 → 证据定位 → 复现规划 → 报告。这是产品立足点，第六阶段不重做。

### 2.2 协作层（假设 H3/H4/H9 驱动）
导师-学生审核流、项目内任务分配、结论修改留痕。若 H3/H4 被推翻，协作功能应降级为可选而非默认。

### 2.3 积累层（假设 H8/H10 驱动）
基准案例库与事实标准化，降低重复审计成本；规则反馈闭环降低误报。若 H8 被推翻，案例库应缩小为「个人历史项目复用」而非公共基准。

### 2.4 连接层（假设 H7 驱动）
仓库版本关联、Notebook 结构化解析、开放 API。若 H7 被推翻（如目标用户主要用 GitLab），连接器优先级调整。

### 2.5 信任层（假设 H5/H6 驱动，横切所有层）
证据可定位、AI 受约束、数据隔离与隐私治理。这是采纳前提，不是可选功能。

## 3. 最有价值的三个升级方向（第六阶段决策）

综合任务书方向、现有架构缺口与上述假设，确定三个优先方向：

### 方向一：团队协作与可追溯审计（对应 A 组 + E 组）
**为什么最有价值**：当前系统无用户模型、无权限、单一共享 admin token，所有读接口完全开放——这既是协作的前提缺口，也是 P0 级安全缺口。导师审核（H3）与操作留痕（H9）都依赖它。
**范围**：用户/组织/项目成员模型、JWT 认证、后端 RBAC、项目级数据隔离、评论与复核流、操作审计轨迹（保留修改前后内容）。
**不做**：实时聊天、复杂审批引擎、跨组织联邦。

### 方向二：可追溯的科研复现基准库（对应 B 组）
**为什么有价值**：每次从零分析相似论文成本高（任务书明确）；案例库是长期壁垒。但必须解决「来源可追溯 + 质量分级 + 不覆盖当前证据」三个信任问题（H8）。
**范围**：案例数据模型（含许可与来源）、标准化事实 schema、结构化+相似度检索（展示匹配依据）、四级质量等级（由验证条件决定，AI 不能自动升级）。
**不做**：论文附件/代码/数据的再分发；向量数据库等重基础设施（先用 SQLite 内结构化检索 + 轻量相似度，验证后再升级）。

### 方向三：受约束的审计规则进化（对应 C 组）
**为什么有价值**：误报摧毁信任（H10）；当前规则硬编码在 Python 常量中，无法维护、无法评估、无法回滚。
**范围**：规则 DB 化（版本/测试样例/启用状态/回滚）、误报反馈闭环（不直接改生产规则）、离线评估、受控 RAG（来源分级展示）。
**不做**：AI 自动学习用户判断并改生产规则；在线学习；不可解释的模型排序。

### 支撑性工作（不作为独立方向，但必须完成）
- D 组外部集成：GitHub 连接器授权模型 + Notebook 增强 + 开放 API（真实第三方授权受环境限制时如实标注 BLOCKED）。
- E 组安全治理：数据分类、隔离、脱敏、保留/导出/删除。
- 前端 12 个新页面与 Qoder Site 迁移。
