# 三类真实用户场景测试报告

**文档编号**：S10-R06  
**日期**：2026-11-19  
**测试方法**：Python httpx 真实 API 调用模拟 + 代码路径审查  
**前端验证**：代码路径审查（无浏览器自动化）

---

## 用户一：本科生/研究生

### 典型任务流程

1. 注册 → 登录 ✅
2. 创建项目 ✅
3. 上传论文 PDF ✅
4. 上传代码 .py 文件 ✅
5. 上传 config.yaml ✅
6. 触发解析 → 看到 chunks 和程序事实 ✅
7. 查看 Verdict summary（部分完成，但有 23 个 VERIFIED） ✅
8. 导出交接包 ✅

### 测试中发现的问题

| # | 问题 | 严重度 | 修复状态 |
|---|---|---|---|
| UG-01 | 上传后看不到解析结果（修复前 LLM Key 硬阻塞） | P0 | ✅ 已修复 |
| UG-02 | 无 LLM Key 时 PDF 材料 fact_count=0（无法 AI 抽取） | P2 | 已知限制 |
| UG-03 | 前端某些页面可能假设了 LLM 抽取已完成的场景 | P3 | 待评估 |

### 结论

修复后，**本科生可以完成"上传→解析→看结果→导出"完整流程**。界面上不会再出现"什么都没有"的空壳。无 LLM Key 时 Verdict 会基于确定性程序事实给出有意义的结论。

## 用户二：科研人员

### 典型任务流程

1. 导入已有科研项目（上传多文件）
2. 管理多个实验版本
3. 比较不同实验结果（reproduction_metrics/project）
4. 查看数据和环境变化
5. 检查研究主张的证据
6. 复审历史审计结果
7. 导出完整科研项目档案（handoff/export）

### 当前能力

| 步骤 | 状态 | 说明 |
|---|---|---|
| 上传多文件项目 | ✅ | 支持 ZIP 批量上传 + 单文件 |
| 多版本管理 | ⚠️ | 项目无版本概念，靠不同 project_id 区分 |
| 实验结果比较 | ✅ | reproduction_metrics/project API 存在 |
| 数据/环境变化追踪 | ⚠️ | materials 有 upload_history，但无显式 diff |
| 研究主张证据检查 | ⚠️ | 需要 LLM 抽取才有主张-代码映射 |
| 历史审计复审 | ⚠️ | parse-tasks 有历史，但无显式审计版本 |
| 完整档案导出 | ✅ | handoff/export 返回 ZIP |

### 结论

对于**单轮审计**（上传材料 → 解析 → 输出报告），科研人员可以完成。但**多版本对比、长期追踪、研究主张映射**等深度科研场景，要么需要 LLM Key，要么需要额外功能开发。

## 用户三：审稿人/课题组负责人

### 典型任务流程

1. 审查论文材料
2. 查看关键研究主张
3. 检查代码和实验材料
4. 查看未验证内容
5. 查看结果冲突
6. 生成结构化审计意见
7. 要求作者补充材料
8. 重新审计

### 当前能力

| 步骤 | 状态 | 说明 |
|---|---|---|
| 审查论文材料 | ✅ | PDF 上传 + 文本块 |
| 关键研究主张 | ❌ | 需要 LLM 抽取（无 Key） |
| 代码/实验材料检查 | ✅ | 静态 AST + config |
| 未验证内容识别 | ✅ | Verdict 自动标记 INSUFFICIENT_EVIDENCE |
| 结果冲突检测 | ⚠️ | 有冲突检测框架（verification layer）但无真实运行结果 |
| 结构化审计意见 | ✅ | report API + handoff 导出 |
| 要求补充材料 | ❌ | 无协作/评论功能（只有 API 级 comments 端点） |
| 重新审计 | ✅ | parse-tasks/{id}/retry 存在 |

### 结论

审稿人场景是 ReproCheck 最关键的使用场景。**当前能做的审计深度有限**：
- ✅ 可以检查"论文 PDF 是否完整、代码结构是否合理、配置参数是否明确"
- ❌ 无法回答"论文声称的这个算法在代码里是不是这样实现的"（需要 LLM 语义级映射）
- ❌ 无法回答"实验结果是否真实可复现"（需要代码执行）

## 总体评价

| 用户类型 | 当前可完成度 | 主要缺口 |
|---|---|---|
| 本科生/研究生 | **70%** | LLM Key（可选，无 Key 也有价值） |
| 科研人员 | **40%** | LLM Key + 多版本管理 + 代码执行 |
| 审稿人/负责人 | **25%** | LLM Key + 代码执行 + 主张-代码映射 + 结果冲突检测 |

**ReproCheck 当前状态：适合做"科研复现性审计的辅助框架"，还不是"独立完成审计工作的完整产品"。** 三个用户场景中，本科生场景最接近可用。
