## 二、已知限制（必须对外说明）

### 2.1 明确限制（不构成阻断）

| 限制 | 原因 | 影响 | 应对 |
|---|---|---|---|
| AI 事实抽取需要 LLM API Key | 商业 API 需授权 | 无 Key 时只有确定性审计 | 文档说明；Key 可选 |
| 真实代码执行需要 gvisor/rootless_docker | 当前 sandbox backend=none | 无法审计运行时行为 | 后续版本集成 |
| OCR 需要 Tesseract + OpenCV | 未集成 | 扫描件 PDF 无法处理 | 后续版本集成 |
| 无 GPU 集群无法复现大规模训练 | 客观硬件限制 | Tier 3 项目（AlphaFold 3 等）只能做静态审计 | 分级处理 |
| 前端无浏览器自动化测试 | 无 Playwright 环境 | 前端 bug 可能遗漏 | 人工走查 + 用户反馈 |

## 五、最终验收结论

### 条件性通过（Conditionally Pass）

**ReproCheck Beta v1.0-candidate-1 具备进入有限 Beta 试点的基本条件，但存在明确限制：**

✅ **可以做的**：
- 完整的确定性审计流程（上传→解析→事实→Verdict→导出）
- 跨用户安全隔离
- 论文 PDF / 代码 / 配置的静态审计
- 交接包生成和完整档案导出
- 真实科研项目的基准测试集（20 个项目元数据）
- pytest 219 项回归 100% 通过

⚠️ **需要说明的限制**：
- AI 事实抽取需要 LLM API Key（推荐使用）
- 真实代码执行需要容器隔离环境
- 扫描件 PDF 需要 OCR 集成
- 部署前必须修复 5 项生产自检失败（配置层面，非代码）

❌ **不适合生产的场景**：
- 需要独立执行完整科研复现实验（需要 GPU 集群 + 隔离环境）
- 需要 LLM 语义级主张-代码映射的深度审稿场景

### 试点建议

1. **试点范围**：邀请 5-10 名科研人员试用，收集真实反馈
2. **试点方式**：在 staging 环境部署（修复 5 项生产配置），不直接部署生产
3. **试点内容**：本科生场景（最成熟）→ 科研人员场景 → 审稿人场景（需要 LLM）
4. **试点期限**：2-4 周
5. **试点成功标准**：至少 1 名科研人员完成"上传→解析→查看结果→导出"完整流程，且表示结果有参考价值
